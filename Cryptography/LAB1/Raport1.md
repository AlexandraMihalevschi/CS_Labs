### Theory

The Caesar cipher is a monoalphabetic substitution cipher that shifts each letter in the plaintext by a fixed number of positions in the alphabet. Formally, for alphabet Σ = {A..Z} and shift k, encryption is E(x) = (x + k) mod 26 and decryption is D(y) = (y − k) mod 26, where letters are mapped to indices [0..25]. A common enhancement uses a keyword to derive a permuted alphabet and then applies the same cyclic shift over this custom alphabet, increasing resistance to simple frequency alignment.

### Objectives

- **Extend** with a second key (keyword) that builds a custom alphabet.
- **Validate** inputs by filtering to A–Z and informing users of non-letters.
- **Demonstrate** encryption/decryption for both variants with interactive I/O.

### Implementation Description

Files: `Caesar_cipher.py`, `Caesar_cipher_2_keys.py`

#### Common utilities

- `get_message_for_encryption(message: str)` uppercases input and keeps only alphabetic characters. If other characters are present, it warns: "Use characters A-Z or a-z!" This ensures ciphers operate strictly over A–Z.

#### Caesar cipher (single numeric key)

- Encryption: `encrypt_message(message, shift)` iterates letters, finds index in the fixed alphabet `ABCDEFGHIJKLMNOPQRSTUVWXYZ`, computes `(i + shift) % 26`, appends mapped character, and prints the result.
- Decryption: `decrypt_message(message, shift)` similarly computes `(i − shift) % 26` and prints the plaintext.
- CLI flow: prompts for message, shift, and operation choice `[1] encryption [2] decryption [3] both` and prints results.

#### Caesar cipher with two keys (numeric shift + keyword alphabet)

- Alphabet derivation: `update_alphabet(key)` builds a permuted alphabet by concatenating the cleaned KEY with the base alphabet and removing duplicates while preserving order (via `OrderedDict.fromkeys`). This yields a 26-letter custom alphabet; it is also printed for transparency.
- Constraint: the keyword must be at least 7 characters (`len(word_key) < 7` leads to exit with a message) to avoid trivial keys.
- Encryption/Decryption: `encrypt_message(message, key, alphabet)` and `decrypt_message(message, key, alphabet)` operate identically to the single-key case but index into the derived alphabet.
- CLI flow: prompts for message, numeric shift, keyword, builds `new_alphabet`, then executes the chosen operation.
